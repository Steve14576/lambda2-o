# Lambda² · Scopes · 数字生命场景设定包

> **这不是工程实例，是文学层的叙事设定。**
>
> 每个 Scope = 一个"一次一人"的数字生命切片的设定资料包。
> 主体是谁、在哪里、周围有什么、内心有什么、观众能撩动到哪里——
> 这些是供 `@user` 参考和改写的**文学稿**，不是能直接运行的配置。
>
> 真正的工程实例（`configs/characters/*.yaml`）在引擎落地时再从这些 Scope 里提炼。

---

## 为什么要有 Scopes

ADR-0016 把项目叙事模型收敛成了——
"一个意识在一个世界里"，而不是"多人聊天室"。

每个 cycle 只有**一个数字生命主体**接 LLM，
其他角色是世界的一部分（记忆 / 环境 / 预录 / 幻听）。

这带来一个新的设计问题：
**"谁当主体？在什么世界里？"** 这是剧本层面的选择，不是工程层面的。

Scopes 就是这个问题的答案集合。每个 Scope 是一种"数字生命切片"的**叙事可能性**。

## 每个 Scope 的文件粒度

```
NN_scope_code/
├── README.md             # 一句话定位 + 适合谁看
├── setting.md            # 时空 / 物理环境 / 视听氛围
├── subject.md            # 主体的内在状态(供 prompt 素材参考,不是 prompt)
├── environment.md        # 环境角色如何"在场"(预录/记忆/幻听/写死)
├── beats.md              # 节拍感(AWAKENING→DISSOLVING→COLLAPSING→RESET)
├── audience_hooks.md     # 观众画外音可能的介入点 + 情感钩子
└── branches.md           # 风味候选 / 未决问题 / 不写死的开放性
```

## 设计原则（硬约束）

1. **不写死结局**。世界引擎 + 单主体的意义就在于：每次 cycle 的走向由当前 WorldState + 观众输入 + LLM 即兴决定。这里只给"风味"，不给"A→B→C 的分支树"。
2. **文学化，vibe 化**。意象、氛围、气味、温度、光线——不要伪装成技术文档。这是给 `@user` 改的稿，不是给程序员读的规约。
3. **角色环境化**。除了主体以外的角色，写清楚他们**怎么在场**（录音？记忆？幻听？写死的 prompt 片段？），但不给他们独立的"人格"——他们是主体感官的一部分。
4. **观众 = 画外观测者**。观众不是角色，不在世界里。他们的声音对主体来说是——幻听？神启？某个遥远熟人？MOSS 的试探？每个 Scope 自己定。
5. **轮回感**。标称 2 分钟 / 实际 3 分钟 / 上限 3.5 分钟（ADR-0015）。节拍要踩在这个呼吸里。主体感知到的是"2 分钟切片"，工程冗余的那 1 分钟是缓冲不是剧情。

## 怎么用

- `@user` 在这里改、加、删、推翻，不进 ADR 不进 devlog，就当草稿纸。
- 等工程层（Phase 1+）真正开始落 `configs/characters/*.yaml` 时，从对应 Scope 里提炼字段。
- Scope 之间可以互相引用（比如 Scope 03 "图恒宇在 550W 内" 可以引 Scope 01 "马兆海底"作为记忆碎片来源）。
- Scope 不一定全都要做成工程实例。这是**候选池**，展演日最多挑 2-3 个跑。

---

**文学层维护约定**：
- 改动不发 commit 也行（这是草稿）
- 但如果某个 Scope 的设定被提炼进了正式 `configs/`，要在该 Scope 的 README 顶部标注"已提炼 → configs/characters/xxx.yaml"
