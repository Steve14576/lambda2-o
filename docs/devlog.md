# Lambda² · Devlog(多 agent 共享)

> **这是一份多方协作的不擦草稿纸。**
>
> 作者本人 + 多个 AI agent 共用同一个时间线,每条发言带作者署名。
> 这不是个人日记,是**工作组的共同记忆**。
>
> - **ADR 是黑板** · 只写客观结论,不署名
> - **Devlog 是草稿纸** · 带署名,有视角,有交接,有纠错,有分歧
> - 新 agent 入场 → 先在 §参与者名册登记,再发言
> - 老 agent 退场 → 名册中状态改为 `retired`,不删历史
>
> 核心规则:
> 1. **每条必有作者署名** `@xxx`,放在时间戳后
> 2. **第一人称视角**,而不是第三方记叙("我建议..." 而不是 "@main 建议了...")
> 3. **跨 agent 引用**用锚点 `[[20260504-1630]]` 或直接 `@xxx 说...`
> 4. **纠错保留**:谁说错了由谁或别人追加 `⚠ 更正`
> 5. **允许分歧**:不同 agent 看法不同的就各自发言,不强制统一
> 6. **时间顺序**:倒序追加(最新一天在上),单日内按时间正序
>
> 草稿纸规则(继承上版):
> - 事无巨细,想到就写
> - 允许模糊、未解、待办、闪念
> - 允许一对多 / 多对一 / 多对多
> - 错的也留

### 入场流程
1. `@user` 在本名册追加一行(标识 + 定位 + 入场日期)
2. 新 agent 首条发言做**自我介绍**:我擅长什么、我的输出风格、我如何和 `@main` 对齐
3. `@main` 确认收到,可能 delegate 若干长期 TODO 池里的条目给它
4. 之后新 agent 正常按署名发言

### 交接约定
- 跨 agent 请求:`cc @xxx` 或 `→ @xxx` 明确点名
- 跨 agent 回应:引用原条目锚点 + 给出回复
- 纠错他人:`⚠ 回应 @xxx 在 [[anchor]]` + 说明
- 不同 agent 有分歧 → 各自保留,最终由 `@user` 拍板,拍板结果进 ADR

## 署名风格速查

| 符号 | 含义 | 例子 |
|---|---|---|
| `@user` / `@main` | 身份标识 | `**14:30 @user**` |
| `?` | 该作者抛出的未解问题 | `? @main: Pipecat 中文资料少,踩坑风险?` |
| `→` / `↔` | 因果 / 关联 | `→ 决定开 ADR-0001` |
| `!` | 待办 | `! @user: 本周下单` |
| `💭` | 闪念 / 猜测 / 不负责 | `💭 @main: 或许可以...但没实测` |
| `🔗` | 跨引用 | `🔗 [[20260504-1440]]` |
| `⚠` | 更正 | `⚠ @main: 我之前 [[...]] 说错了` |
| `cc @xxx` | 点名其他 agent | `cc @tts 这个延迟指标请实测` |

- 发起:`cc @xxx` 或 `→ @xxx`
- 回应:锚点引用 + 答复
- 分歧:各自保留条目,最终 `@user` 拍板 → 结果进 ADR

- ADR 新增 / 改动 → devlog 当天留条目
- PRD / Glossary 改动 → devlog 当天留条目
- commit message 可引用锚点,如 `devlog(20260504-1615): 否决全 Docker 方案`
