## 1. 前一日准备

### 1.1 硬件打包清单
- [ ] 笔记本 + 电源 + 电源适配器
- [ ] USB 耳机 × 2(主 + 备用未拆封)
- [ ] USB 延长线 × 2
- [ ] 理线夹 / 魔术贴
- [ ] 一次性耳套(≥ 50 个)
- [ ] 消毒湿巾
- [ ] 随身 WiFi + 充电线
- [ ] 排插
- [ ] 展位立牌 + 贴纸(详见 [compliance.md §2.3](./compliance.md#23-展位立牌文案强制))
- [ ] 打印版本手册(本文档)
- [ ] 小台灯(可选)
- [ ] 水、湿纸巾、创可贴

### 1.2 软件自检
前一晚至少执行一次完整联调:
```bash
just check         # 环境自检:设备 + API key + 学长服务器可达
just bench         # 延迟压测:端到端首音 < 2.5s
just dev           # 跑 10 轮模拟,无崩溃
```
任一项失败**不出门**,修了再说。

### 1.3 备份策略
- 学长服务器 TTS 容器状态:跑 24 小时以上稳定
- 预录兜底音频库:完整生成一次(`just gen-fallback`)
- 本地 CosyVoice 2 fallback 至少能跑(不要求快,要求能出声)
- 开发分支打 tag:`booth-day-YYYY-MM-DD`,万一现场改崩了能回滚

## 2. 开场前 30 分钟 Checklist

### T-30 分钟 · 硬件部署

- [ ] 到场选位(靠墙、避开强光、方便走线)
- [ ] 接电源、开排插、确认稳定供电
- [ ] 笔记本开机、连展位 WiFi(如有)、连随身 WiFi 备网
- [ ] USB 耳机插入,延长线连好
- [ ] 耳机挂在挂架上,线理顺用夹子固定
- [ ] 展位立牌摆正(观众面 + 作者面)
- [ ] 耳套盒 + 湿巾盒 + 垃圾袋就位

### T-20 分钟 · 软件启动

- [ ] 打开终端,`cd lambda2-o`
- [ ] `just check` —— 所有项绿色:
  ```
  ✔ INPUT_DEVICE  : Logitech USB Headset H390 (id=3)
  ✔ OUTPUT_DEVICE : Logitech USB Headset H390 (id=3)
  ✔ SAMPLE_RATE   : 24000
  ✔ LLM_API       : qwen-max reachable (latency 220ms)
  ✔ TTS_REMOTE    : ws://tts.mentor.local:9100 reachable (latency 35ms)
  ✔ TTS_LOCAL     : loaded (fallback ready)
  ✔ PRERECORDED   : 147 clips loaded
  ```
- [ ] 任一项红色 → 进 [§5 故障应对](#5-常见故障应对)

### T-10 分钟 · 联调试运行

- [ ] `just booth` 启动,状态进入 IDLE
- [ ] 戴上耳机自测一轮完整流程:
  - [ ] 环境底噪能听到(微弱机房嗡鸣)
  - [ ] "你好?" → 5 秒内听到任一角色回应
  - [ ] 打断测试:TTS 播放中说话 → 应 <200ms 停
  - [ ] 等 2 分钟 → 自动 reset 到 IDLE
- [ ] 再跑 1 轮,听到音质正常、无爆音、无卡顿

### T-5 分钟 · 请同伴试玩

- [ ] 找一个没接触过项目的同学当"第 0 号观众"
- [ ] 观察:她能自然进入、没出现明显 BUG、2 分钟完整出来
- [ ] 询问主观感受,记录反馈(仅用于事后改,不改展位日代码)

### T-0 分钟 · 开张

- [ ] 展位立牌朝外
- [ ] 你站在桌侧,面带微笑
- [ ] 不推销,让路过的人自己好奇

## 3. 单轮接待流程

### 3.1 总时长:约 3 分钟 / 人
- 讲解 + 戴耳机:30 秒
- 体验:120 秒(固定)
- 收尾:30 秒

每小时接待约 **18-20 人**(留 5% 缓冲)。

### 3.2 Step 1 · 观众到来(10 秒)
**说什么**:
> "戴上耳机就行,一共两分钟。里面会有声音跟你说话,你也可以回应它。"

**做什么**:
- 取一对新耳套套上耳机
- 简单擦一下耳机外壳(湿巾)
- 把耳机递过去

**不说什么**:
- 不剧透角色
- 不说"这是流浪地球"(让观众自己意识到)
- 不说"AI"、"LLM"、"语音合成"(破沉浸)

### 3.3 Step 2 · 戴耳机(20 秒)
- 观众戴好,问一声:"能听到底噪吗?"(那个嗡鸣)
- 底噪能听到 = 音频通路 OK
- 确认后说:"好,开始了。"
- 按下**启动键**(代码里预设一个键绑定,如 F9,触发 `cycle_start`)

### 3.4 Step 3 · 体验(120 秒,主进程自动)
**你在这 2 分钟做什么**:
- **不打扰观众**
- 眼睛扫一下笔记本屏幕(隐藏 debug 面板):
  - 当前 stage
  - elapsed 计数
  - 最近一条 LLM 输出(不用细看,只看"还在跑")
- 观察观众表情:
  - 沉浸 → 很好,不用动
  - 困惑/尴尬笑 → 不用动,也是正常反应
  - **摘耳机/表情不适** → 立即按**中止键**(F10),进入 §5.F
- 观察耳机线:别让下一个观众绊倒

**什么时候打断**:
- 观众主动摘耳机
- 观众身体不适
- 观众超过 1 分钟沉默且表情不对劲
- 技术故障(屏幕弹错、声音断)

### 3.5 Step 4 · 结束(20 秒)
- 2 分钟到,自动重置到 IDLE
- 观众会听到一段"意识归零"的渐弱音 + 完全静音 3 秒
- 你接过耳机,说:"好了。"
- 拆掉耳套扔垃圾袋
- 湿巾擦耳机 + 麦克风 + 自己手
- 问一句:"感受怎么样?"(简短,不要逼人回答)

### 3.6 Step 5 · 过场(10 秒)
- 下一个观众到 → Step 1
- 没有下一个 → 耳机挂回架子,喝口水

## 4. 每小时检查项

整点(或整点前 5 分钟,利用等人间隙)快速过一遍:

### 4.1 硬件
- [ ] 耳机有没有掉耳套残渣 → 擦一下
- [ ] USB 线接口有没有松 → 拔插一次
- [ ] 笔记本温度 → 摸一下底部,烫 → 加散热(外接风扇/架高)
- [ ] 随身 WiFi 电量 → <30% 插充电线

### 4.2 软件
- [ ] 看终端日志最近 100 行,有没有 ERROR
- [ ] 看当前 `cycle_id` 数,对比记录,确认没崩过
- [ ] 看延迟监控(如果打开):平均首音延迟 < 2s

### 4.3 耗材
- [ ] 耳套还剩几个?<10 个 → 补货或上门店买
- [ ] 湿巾还剩多少?< 10 片 → 补

### 4.4 你自己
- [ ] 喝水
- [ ] 坐下/站起来活动
- [ ] 记录一两个观众的反馈关键词(记在小本上,事后总结)

## 5. 常见故障应对

### 5.A · 耳机没声音

**症状**:观众说"听不到"、或底噪都没有

**排查步骤**(30 秒内):
1. 看 Windows 系统音量:不是静音
2. 看任务栏音频设备:确认选的是 `Logitech USB Headset H390`
3. 重插 USB 耳机,等 3 秒系统重新识别
4. `just check` 再跑一次看 INPUT/OUTPUT 是不是还是 id=3

**仍不行**:
- 换备用耳机(未拆封那条)
- 跑完当前观众后重启主进程

**兜底**:
- 告诉观众"设备暂时出问题,1 分钟后再来"
- 修不好 → 改为预录模式(`TTS_BACKEND=prerecorded`)简化体验继续

---

### 5.B · 麦克风不收音(观众说话没反应)

**症状**:LLM 没路由到任何角色,stage 仍在推进但全程无回应

**排查**:
1. 看 terminal:有没有 `UserSpeakingStarted` 事件
2. 没有 → VAD 阈值太高 or 设备选错
3. 临时降低 VAD 阈值:
   ```
   VAD_THRESHOLD=0.3 just booth    # 默认 0.5
   ```
4. 或直接切换到 "轮询提问模式"(后文):每 20 秒让 DM 主动抛一句,不依赖观众说话

**兜底**:
- 有时候观众就是不说话,那是**体验的一部分**,不算故障
- 但持续 60 秒 VAD 无触发 → 大概率麦克风挂了

---

### 5.C · 网络变慢/断开

**症状**:LLM 首包 >3s,或 TTS WebSocket 断开

**排查**:
1. `ping 8.8.8.8` → 有回应?
2. `ping tts.mentor.local`(学长服务器)→ 有回应?
3. 打开手机 → 看展位 WiFi 有没有挂

**应对**(优先级):
1. **切随身 WiFi**:断开笔记本展位 WiFi,连随身 WiFi 热点
2. **切本地 TTS**:`.env` 改 `TTS_BACKEND=local`,重启主进程(约 30 秒加载模型)
3. **切预录模式**:`TTS_BACKEND=prerecorded`(几乎秒启,音色固定)
4. **告示暂停**:如果彻底不可用,立牌翻面写"装置暂停 10 分钟"

**沟通话术**:
> "网络有点不稳,稍等两分钟。"

---

### 5.D · LLM API 报错

**症状**:terminal 连续刷 `LLM rate limit` / `API timeout` / `401 unauthorized`

**排查**:
- **401** → API key 过期或余额耗尽。进备用 key(`.env` 留好 `QWEN_API_KEY_BACKUP`)
- **429 rate limit** → 调用太快,降低并发到 1
- **timeout** → 切换 provider(`LITELLM_PROVIDER=doubao`)

**兜底**:
- 全挂了 → `TTS_BACKEND=prerecorded + LLM_BACKEND=canned`
- canned 模式:每 15 秒播放一条预写的台词,纯单向广播,不再理观众
- 这是**体验降级**但不崩场的保底

---

### 5.E · TTS 卡住(声音中间停了)

**症状**:角色说话说到一半突然没声,但 terminal 还在正常输出

**排查**:
- 学长 TTS 服务 OOM?WebSocket 断了?
- 看日志有没有 `ws connection lost`

**应对**:
- 主进程应该**自动重连**(代码里要做,Phase 3 实现)
- 自动重连失败 → 手动重启主进程(当前观众体验会被打断)
- 记录时间 + cycle_id,事后复现

---

### 5.F · 观众中途摘耳机 / 表情不适

**症状**:观众明显想中止

**操作**:
1. 立即按**中止键 F10**(触发 `cycle_reset`)
2. 耳机接过来
3. 温和地问:"是不是太压抑了?不好意思。"
4. 不追问,不强留
5. 给一张纸 + 笔:如果愿意,可以写下反馈(匿名)

**事后**:
- 记下这轮的 cycle_id + stage + 大概原因
- 连续 2 次不适 → 考虑把 COLLAPSING 期的强度下调

---

### 5.G · 主进程崩溃(Python 堆栈报错)

**症状**:terminal 一片红,主循环退出

**操作**:
1. **冷静**,告诉观众"一分钟就好"
2. 复制最后的堆栈 trace(手机拍屏或 `>> crash.log`)
3. `just booth` 重启(约 10-20 秒)
4. 回到 IDLE,继续

**事后**:
- 连续 2 次崩 → 停展,排查
- 复盘 trace,定位模块

---

### 5.H · 电源问题

**症状**:排插跳闸 / 电压不稳 / 笔记本直接黑屏

**操作**:
- 笔记本有电池能坚持 30-60 分钟,不怕瞬断
- 但随身 WiFi 可能断电 → 提前充满或接充电宝
- 排插跳闸 → 换一个插座 / 通知展位管理员

**预防**:
- 排插别插太多大功率设备(不要接热水壶)
- 排插带过载保护的款

---

### 5.I · 被围观太多不好操作

**症状**:排队太长、围观者太多、你自己压力大

**应对**:
- 拉一根警戒线(带一卷便携伸缩带 ¥15)
- 让队伍在距离桌子 1.5 米外
- 写一张排队牌:"当前约 X 人在前,等候约 X 分钟"
- 实在不行 → 暂停 10 分钟休息

---

### 5.J · 观众问"这是什么 AI"

**话术**:
> "多种 AI 组合,对白是实时生成的,声音也是合成的。具体技术栈在 GitHub 上会开源。"

**不说**:
- 具体厂商名(qwen、doubao、OpenAI)—— 无关紧要
- "微调"、"训练"—— 让人误以为收集数据
- "这是我第一个项目" —— 不谦虚不自负,专业感

## 6. 收场流程

### 6.1 最后 15 分钟
- 立牌"本展位今日结束,非常感谢"
- 不再接新观众,让已排队的人走完
- 不赶人,但也不主动延长

### 6.2 收场执行
- [ ] `just booth` 终端 Ctrl+C 优雅退出
- [ ] `python scripts/cleanup.py` → 清除临时音频 + 日志(合规要求)
  - 删除 `/tmp/lambda2-*`
  - 删除 `logs/*.log.today`(保留一份加密备份自己看)
  - 清空 `assets/prerecorded/cache/`
- [ ] 笔记本关机
- [ ] 硬件拆卸:耳机擦干净收盒、延长线收好、排插收好
- [ ] 垃圾带走(耳套、湿巾、纸巾)—— **不要留桌面上**
- [ ] 桌面擦一遍

### 6.3 事后 24 小时内
- [ ] 日志脱敏后存档(留下 crash trace 和延迟数据,**不留**对话内容)
- [ ] 小本子上的反馈关键词整理到 `docs/feedback-YYYY-MM-DD.md`
- [ ] 列出故障次数 + 类型,决定是否需要硬件/代码改动
- [ ] **如果连续两天都要展**:每晚复盘完当天,确认次日还能用

## 7. 紧急联系 + 应急话术

### 7.1 联系人清单(展位日带在手机)

| 角色 | 联系方式 | 能做什么 |
|---|---|---|
| 自己 | — | 主负责 |
| 学长(服务器管理) | 电话 / 微信 | 重启 TTS 容器、检查服务器 |
| 展位管理员/同学 | 电话 | 求助电源、换摊位 |
| 校医 | 电话 | 观众身体不适 |
| 保安 | 电话 | 冲突、突发事件 |

> **提示**:前一天把这些联系方式抄在纸上 + 存手机两处。
> 笔记本挂了手机还能用。

### 7.2 应急话术模板

**观众不适**:
> "不好意思,装置强度比想象中高,需要喝水休息一下吗?"

**需要暂停**:
> "装置暂停调试中,10 分钟后恢复,抱歉。"

**有人质疑内容**:
> "这是校园嘉年华的同人创作,非商用。立牌上有详细说明。"

**有人想拍照录像**:
> "可以拍展位外观,但耳机里的声音请不要录制上传,已经在立牌声明里。"

**有人想付费体验**:
> "免费的,就是学习项目,玩就是了。"

**有人问能不能做 XXX(多人版、家用版、商业化)**:
> "现在只是嘉年华展演,后续会开源在 GitHub,你可以 fork。"

**连续故障撑不住**:
> "今天装置状态不稳定,提前结束,明天见。"
> —— 不硬撑,及时收场。

---

## 8. 最重要的三条

1. **不崩场 > 体验完美**。当天任何时候都宁可降级到预录模式,也不要让主进程挂着黑屏。
2. **观众安全 > 剧情完整**。有任何不适苗头立即 F10 中止,不纠结"但这段刚好是高潮"。
3. **不扩散 > 传播效果**。别人想录音录像一律委婉拒绝,参考 [compliance.md](./compliance.md)。

---

**展位日你只需要做三件事**:
- 戴耳机给观众
- 看着不崩
- 收拾干净走人

其他的,代码和 prompt 已经替你做完了。
